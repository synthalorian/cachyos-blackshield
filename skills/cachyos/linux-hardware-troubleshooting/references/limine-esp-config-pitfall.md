# Limine bootloader config on CachyOS — ESP vs source config split

CachyOS uses Limine with a **two-tier** bootloader config that trips people up when adding kernel cmdline params (e.g. `pci=rescan`, `pcie_aspm=off`, `drm.edid_firmware=...`).

## Two tiers

1. **Source config** — `/etc/default/limine`. Declarative. `KERNEL_CMDLINE[default]+=` appends kernel parameters. This is what you **edit** when changing cmdline params.

2. **ESP config** — `/boot/limine.conf`. What the bootloader **actually reads**. Auto-generated by `limine-entry-tool` from the source config + kernel package metadata. Each entry has its own `cmdline:` line.

## The trap

Adding a param to `KERNEL_CMDLINE[default]` in `/etc/default/limine` does **not** take effect on the current boot if the ESP's `limine.conf` entry for the active kernel still has the old cmdline. The kernel reads `/proc/cmdline` from the ESP, not from `/etc/default/limine`.

```bash
# WRONG verification — reads the source, not the live cmdline:
grep "KERNEL_CMDLINE" /etc/default/limine

# RIGHT verification — reads what the kernel actually booted with:
cat /proc/cmdline | tr ' ' '\n' | grep pci=rescan
```

If the param is missing from `/proc/cmdline`, it's not active — even if `/etc/default/limine` looks correct.

## How to sync

After editing `/etc/default/limine`, force the ESP to regenerate:

```bash
sudo limine --enroll-config
```

Or reboot — kernel installs on CachyOS typically trigger a regeneration via pacman hooks. But manual edits to `/etc/default/limine` do NOT auto-sync until something triggers a regeneration.

## EDID override specifics

`drm.edid_firmware=HDMI-A-1:edid/skg-2560x1080.bin` in the cmdline tells the `drm` module to use a fake EDID blob for the named connector. The blob must exist at `/usr/lib/firmware/edid/skg-2560x1080.bin` (owned by `linux-firmware`, survives kernel updates). If missing, the override silently falls back to the real EDID — verify before rebooting after a kernel change:

```bash
ls -la /usr/lib/firmware/edid/skg-2560x1080.bin
```

## Session context

Discovered 2026-08-13: `pci=rescan` was added to `/etc/default/limine` but the ESP's `/boot/limine.conf` hadn't been regenerated, so the running kernel did not have `pci=rescan` in its cmdline despite `/etc/default/limine` showing it. WiFi card ghosting on reboot was not fully defended until the ESP was patched directly.
