## Key Architecture Decisions

### Why Not Just a Rust DSL?
User explicitly rejected Rust-flavored syntax: "I want shark to be unique" and "universal for all development." Led to abstracting over language-specific concepts (resources instead of structs, actions/queries instead of `&mut self`/`&self`).

### Resource Abstraction
`resource` keyword encapsulates lifecycle (init, state, cleanup, actions, queries) without exposing target-language ownership models. The compiler handles Mutex, Arc, borrow checking, etc.

### Constraint System
Constraints are key-value pairs attached to modules/functions. Not just documentation — the `openshark check` command validates them. Examples:
- `@constraint safety: "thread-safe"` → compiler injects locking
- `@constraint test_coverage: 90` → build fails if coverage < 90
- `@constraint max_latency_ms: 50` → performance test gate

### Harness Provenance
Every function can declare:
```shark
@generated by: "hermes"
@tokens: 1247
@session: "uuid"
@refactored from: "claw-code:init"
```

This enables:
- `openshark stats --by-harness` — compare agent efficiency
- `openshark check` — detect intent drift
- Historical analysis of which agent writes better code for what
